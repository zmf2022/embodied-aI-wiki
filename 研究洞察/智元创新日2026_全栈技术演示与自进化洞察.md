## 一、核心判断

2026 智元创新日讨论的不是单一机器人新品，而是从模型 Benchmark 走向「有效自主作业」：**可用本体 → 专业部署 → 泛化具身基础模型 → 群体经验共享 → 智能自举**。关键分成三条闭环：

1. **Agentic Robot Learning 研发闭环**：任务失败、弱技能或主动探索目标 → Research Agent 查文献、提出假设 → Coding Agent 编写技能代码或训练程序 → 仿真/BC/RL/VLA 微调 → 独立验证 → 注册可复用技能。缺足自适配只是其中一个演示案例。
2. **模型训练闭环**：GO-3 / WRAM 预训练 → Genie Evolver 真机/物理仿真/世界模型后训练 → Genie Master 部署后经验与策略改进。
3. **生产力闭环**：上岗 → 连续自主任务 → 异常恢复 → 数据回流 → 新版本部署 → Worken 与质量/成本评价。

Worken 不替代任务成功率、安全、成本和独立泛化评测，它试图补足「能演示」与「能生产」之间的度量空白。

## 三、核心方向：Agentic Robot Learning / Embodied Autoresearch

### 名称与研究边界

| 名称 | 角色 | 是否改变模型权重 |
|---|---|---|
| Code-as-Policy | LLM 生成 Python/技能调用程序，实现任务操作与修复 | 不必 |
| Agentic Robotics | 规划、观察、工具调用、控制、反馈恢复的广义机器人 Agent 系统 | 不必 |
| **Agentic Robot Learning** | Coding Agent 自主研究、探索、编码、训练、评测与持续改进技能 | 可以 |
| **Embodied Autoresearch** | 自动实验、假设搜索、代码修改、回归验收的研发平台 | 视实验而定 |
| **Self-Improving Robot Skills** | 经验证能复用、可迭代升级的代码技能与神经策略资产 | 可以或不可以 |

**最准确的研究方向是 Agentic Robot Learning，平台名称沿用 Embodied Autoresearch，目标是 Self-Improving Robot Skills。** 这比将所有自我提升称为 Code-as-Policy 更精确。

### 技术主架构（上半身/机械臂优先）

~~~mermaid
flowchart TD
  A[任务要求/历史失败/主动探索课程] --> R[Research Agent: 查文献/提出假设]
  R --> C[Codex/Claude Code: 代码与训练方案]
  C --> P[代码技能: API/抓取/恢复/感知]
  C --> T[学习策略: BC/RL/VLA/奖励/训练数据]
  P --> S[Isaac Lab/RoboLab/RoboDojo 仿真试验]
  T --> S
  S --> E[冻结集评测: 泛化/安全/成本/人工介入]
  E -->|通过| K[技能库: 版本/前置条件/成功验证/恢复策略]
  E -->|失败| R
  K --> X[在线技能选择与安全执行]
  X --> L[任务异常/环境差异/新数据]
  L --> A
~~~

需要明确划分三种改善机制：

- **代码级技能进化**：生成或修复 Python 控制/技能调用脚本，跨任务复用；不一定微调 VLA。代表 ASPIRE 和 RATs。
- **模型级策略进化**：自动调整数据、奖励、训练超参及代码，执行 BC/RL/VLA 微调并生成新 checkpoint。代表 ENPIRE 中的学习策略路径。
- **Harness/记忆级进化**：根据反馈改进任务分解、技能参数、主动观测、故障恢复，不修改模型也能提高整体成功率。与 Genie Master / Physical RSI 中 Harness RSI 对应。

每个可复用技能至少有接口契约：技能名称、目标、输入/输出、前置条件、可用本体、接触/速度/力安全限制、成功判定、异常恢复、测试记录、模型/代码版本与回滚入口。

### 值得直接研究的开源项目

| 项目 | 直接价值 | 边界 |
|---|---|---|
| [ASPIRE](https://github.com/NVlabs/ASPIRE) | Coding Agent 生成、诊断、修复 Code-as-Policy，积累代码技能库 | 不能等同于 VLA 权重训练 |
| [RATs](https://github.com/Playful-RATs/RATs) | 提前主动提出探索任务，沉淀成功代码技能，提升未见任务表现 | 原项目明确不用梯度和 RL |
| [ENPIRE](https://github.com/NVlabs/ENPIRE) | 机器人环境复位、Rollout、任务验证与策略自改进，兼容 Code-as-Policy、BC、RL | 真机需要独立的复位、奖励、校准与安全预检 |
| [SEAR](https://sear.bot/) | 明确区分 Code-as-Policy、Agent-as-Policy、Auto-Research，并研究经验继承与跨环境评测 | 截至 2026-10-30 项目仓库声明完整代码尚待发布；技能库也可能造成负迁移 |
| [RLE-Bench](https://github.com/RLE-Bench/RLE-Bench) | 评估 Coding Agent 对控制、策略开发、感知估计和机器人机械设计的研发能力 | 需固定 Harness、时间和算力预算 |
| [RACaP](https://github.com/Robo-Harness/racap) | 离线自动进化代码技能，在线仅选择已验证 API；父候选同预算评测 | 独立核实实现成熟度 |

**SEAR 的关键警示**：同一个模型继承技能库后并不一定提升，有时错误经验造成负迁移。必须按未见初始状态、未见扰动、未见任务、跨仿真/跨本体逐级评测，并对「更多尝试次数」「更长上下文」「额外训练算力」设预算匹配对照，不把增加搜索预算误判为技能真正增长。

### 按当前资源落地

**第一阶段，先让 Agent 主动学会更多技能，不急于训练大模型。** 以药房抓取、条码翻转、传送带放置和样本库设备交互为任务群，搭建 reset / observation / action / verifier 接口。让 Codex/Claude 提出未覆盖的扰动场景，自动写候选技能、运行仿真、诊断失败，通过冻结评测后纳入技能库。对比空技能库、人工编排与自动进化技能库在未见场景的差异。

**第二阶段，让 Agent 自主改善已训练策略。** 对程序级修复无效的接触和动作策略问题，Agent 自动产生数据采样、奖励、训练脚本或超参候选，调用现有 RL/BC 训练并比较策略 checkpoint。记录 GPU 小时、数据量、成功率增益、随机扰动退化与人工介入。

**第三阶段，形成主动探索和版本晋升制度。** Agent 在观察到低成功率、新物体/场景或业务任务变化时提议实验；系统设置调用预算、训练/评测隔离、安全阈值、版本回滚，不允许 Agent 改动评测集定义与机器人安全策略。

不用把人形下半身作为研究前提，机械臂和双臂操作就足以验证这条路线。大模型负责低频研发与编排，实时运动由现有 VLA、RL 策略或经典控制器承担。

### 智元移除足部并自主站立：保留为一个案例

这段视频的价值是说明 Agent 有潜力自动承担一部分机器人学习工程师工作：检查结构变化、检索相关论文、修改代码、运行物理仿真与 RL，最终获得恢复站立策略。**它不是智元整场发布会的中心，也不是本研发路线的唯一对象。** 目前缺少完整执行日志，不宜断言整个流程已经无人介入，仍需验证仿真模型与奖励的编写归属、训练时间、人工 checkpoint 选择以及真机重复成功率。

## 四、GO-3 Preview 与 WRAM

WRAM（World Reasoning Action Model）将环境理解、未来状态预测与动作生成连接。公开报道的子机制：

- **CoAE**：控制导向视觉表征；报道称视觉 token 相对 DINOv3 对照约 1/16、动作恢复误差改善 35%。该数值不是整体任务成功率。
- **SVP**：Single-step Visual Planner，预测下一关键未来状态。
- **IDM**：Inverse Dynamics Model，根据当前与目标未来状态生成动作。
- **KASO**：Knowledge-Aligned Selective Optimization，训练中从多个候选未来筛选更一致的目标，不应断言上线时每步实时「四路搜索」。

~~~mermaid
flowchart TD
 A[观测 / 任务 / 机器人状态] --> B[VLM + CoAE]
 B --> C[SVP: 预测未来视觉状态]
 C --> D[IDM: 推断动作]
 D --> E[动作生成与反馈]
 K[KASO: 训练阶段候选选择] -.约束训练.-> C
 E --> A
~~~

建模直觉：传统 VLA 是观测与语言到动作；WRAM 增加未来状态作为中介约束。和 GPT-as-Policy「外部 LLM 评估/纠正 VLA 动作」不同，WRAM 尝试把未来预测融入具身策略。但必须用推理延时、物理失败、消融和分布外评测判断收益。

**榜单口径**：RoboDojo 报道中 61.90 分/56.42% 平均成功率对应 **GO-3 Nano Preview**，不能与完整 GO-3 Preview 混为一谈；RoboTwin 的约 85.01% 等成绩需要同任务集、扰动、执行预算与 Agent 条件才可比较。完整 GO-3 Preview 计划 2026 年底开源（截至 2026-10-30）。

## 五、Genie Evolver / Genie Master / Physical RSI

- **Genie Evolver**：百台级真机与物理仿真、世界模型结合的后训练体系；不是单一模型。
- **Genie Master**：机器人部署后推理、技能调用、执行反馈、异常恢复与经验改进的具身 Agent。
- **EEP（Embodied Execution Protocol）四类接口**：Capability（能调用什么）、Guidance（怎么执行）、Feedback（执行后发生什么）、Continuity（如何在中断后继续）。
- **Harness RSI**：记忆、提示、技能参数和工作流规则更新；不必修改模型权重。
- **Policy RSI**：从任务恢复和真机尝试中收集、治理轨迹，更新动作策略参数。两条改进机制必须分别计算收益。

便利店挂货案例中，机器人面对被遮挡的小挂钩，尝试使用左腕相机近距离补充观测，再由右手操作，体现 **Active Perception**；外卖打包案例中夹爪和袋带缠绕，通过改变退出与重试方式恢复，体现 **Feedback + Recovery**。报道的完整任务成功率 28.6% → 85.7%（第 1 至第 5 天）属厂商案例，缺少独立测试、样本量、人工介入与版本细节。

~~~mermaid
flowchart TD
 A[任务目标 + 任务记忆] --> C[Capability / Guidance]
 C --> P[动作 Policy + 机器人]
 P --> F[Feedback + 新视角]
 F --> Q{任务达标?}
 Q -->|是| N[Continuity / 下一步骤]
 Q -->|否| R[异常诊断 + 重规划/恢复]
 R --> P
 F --> L[Harness RSI: 经验规则]
 F --> T[Policy RSI: 训练轨迹]
 L --> A
 T --> P
~~~

### Rollback：视频背后的真实研究

论文/官方项目：https://rollback-wm.github.io/ ，https://arxiv.org/abs/2610.36068 。

同一 π0.5 初始策略，比较 RISE + GE-Sim 2.0 与 Rollback 真机成功率：

| 任务 | 对照 | Rollback | 绝对提升 |
|---|---:|---:|---:|
| 抽积木 | 58.67% | 69.33% | +10.66 pp（论文报告约 +10.67） |
| 投球入桶 | 28.89% | 40.00% | +11.11 pp |
| 桌面冰壶 | 52.59% | 64.44% | +11.85 pp |

Rollback 用世界模型回到重要决策状态，通过 MCTS 探索多条动作分支，比较同一起点的不同未来并形成动作价值监督，不另训练价值网络；模型与真机策略协同更新。每节点 Action Chunk 为 50 个控制步、30Hz，约 1.67 秒。报道实验表明 World Model RGB L1 从 19.52 降至 12.96，误差增长倍数从 1.90× 降至 1.38×；这不是全物理准确率。**视频成功个例不能替代这些统计结果。**

## 七、Genie Sim、Genie Studio 与数据引擎

**Genie Sim Engine / Dream**：Engine 是接触/柔性物理求解，Dream 是学习式未来状态预测，不能混同。公布的 22 任务×4 本体仿真-真机得分相关性 96.7% 是相关性而非成功率或逐帧误差；真正需要绝对误差、失败模式一致性、泛化与成本。仓库 https://github.com/AgibotTech/genie_sim ，10 月 30 日时重大更新预告在 11 月 2 日，不能将所有新功能视为已开源。

**Genie Studio 2.0**：Flywheel 数据/模型闭环、Agent 工作流/技能编排、Monitor 多机运维；天级部署指部分定制场景，不是所有机器人零配置即部署。

**AGIBOT WORLD 2026 具身推理数据**：首批约 150 小时，更重视任务目标、状态、步骤边界、Dense Prompt、扰动和条件分支。重点不是「补货三次」，而是「根据当前库存与目标条件决定补多少」。

### CEL 群体经验学习：还需要什么验证？

10/30 的 CEL 在完整技术路线中连接单体自主进化与群体经验共享。根据智元官方预告，其百台级真机集群原型已验证，但公开口径不足以独立确认具体的模型融合算法、任务间经验收益和机器人本体差异处理。

技术上需区分三种共享：①共享经过验证的代码技能、提示与恢复经验；②跨机器人治理轨迹后进行训练或蒸馏；③直接聚合模型参数。只有第一种可在较少硬件假设下尝试复用，后两种要进一步考虑关节拓扑、观测/动作表示、接触动力学和灾难性遗忘。

对当前平台，应先把任务状态、错误类型、Skill Contract、验证数据集和实验日志统一起来，再考虑不同本体之间的神经策略迁移。群体规模不是泛化能力的直接证据。

## 八、AGILE、硬件、WITA、Link-U OS

- **AGILE**：全身运动感知控制与自主进化研究方向；X2 搬运中受扰目标重拾说明可适应变化，但不代表所有恢复逻辑来自统一 VLA。
- **AHA3**：混合工业通信、GaN 驱动、空间定位、融合通信等；关注持续扭矩/热管理而非峰值性能。
- **G2 Max**：官方标称单臂 20kg、双臂合计 40kg、峰值 50kg、7DoF 力控双臂、亚毫米级精度、双电池热插拔；要核实节拍、重复定位、温升、MTBF、人工接管。
- **液冷/触觉/MEgo Glove**：公布关节液冷相对风冷 7× 散热、3× 持续扭矩等指标；OmniPicker 3 约每指 70 触觉点；MEgo Glove Ultra 0.01 N、最高 1000Hz。厂商条件未统一，不宜跨产品比较。
- **WITA-OMNI 1.0**：视觉、语音、文本、表情、肢体协同；公布最快约 400ms、平均约 600ms 是交互响应，不是 VLA 1kHz 运动环性能。
- **Link-U OS 1.0**：AimRT、ROS2、RPC/Topic、驱动/运行时/构建等；Alpha 已公开，完整版本计划年底进一步开放。仓库 https://github.com/Link-U-OS/Link-U-OS 。

## 九、Worken 与五次跃迁

Worken（有效智能工时）= **活跃机器人数量 × 自主工作时长 × 产出效能比**。这不是单次动作成功率，也不是机器人运行总时间。有效性仍须考虑合格产出、人工介入、安全、节拍、维护和部署成本。跨医疗药房、工业装配、康养护理等不同任务应分别定义岗位基准；Worken 尚不是统一公认的结算标准。

发展路线：可用身体 → 垂域部署 → 泛化基座模型 → 群体经验学习 → 智能自举。10 月 30 日 CEL 群体经验学习仍需独立审查算法与原型验证；11 月 2–3 日六台 G2 便利店长时直播是未来公开验证节点，不能提前当作已有结果。

## 十、面向盈康的 Agentic Robot Learning 研发路线

不复制智元全栈，沿用 Isaac Lab / RoboLab / RoboDojo / RoboTwin / 现有本地模型，以「场景真实问题 + 可复现评测」建立差异化。

| 优先 | 实验方向 | 实验设置 | 关键指标 |
|---|---|---|---|
| P0 | 自主技能发现与复用 | ASPIRE/RATs：任务生成、技能候选、执行验证、持续积累 | 未见任务提升、技能覆盖、人工介入、Agent 成本 |
| P0 | Genie Master 风格主动感知与任务恢复 | 药盒条码遮挡、抓取失败、物品掉落；固定重试 vs VLM 补视角 vs 有记忆 Agent | 恢复率、接管次数、恢复时延、误判 |
| P1 | 自动训练与模型级策略提升 | ENPIRE：Agent 自动提出数据/奖励/训练候选，BC/RL 后训练、固定回归 | 新旧 checkpoint 性能、GPUh、人工介入、回归退化 |
| P1 | Rollback 风格关键节点反事实探索 | Isaac Lab 保存关键状态，分叉不同抓取/夹持/放置动作 | 提升 pp、训练样本、分支预算、失败类型 |
| P1 | WRAM vs 外部动作校核 | 原始 VLA vs VLM 校核 vs 未来状态预测 | 泛化、动作延迟、有效预测率、成本 |
| P1 | Sim2Real 一致性 | 摩擦、碰撞、位置偏差、传感器延迟、资产不同 | 排名相关性 + 绝对误差 + 失败一致性 |
| P2 | 连续业务生产力评测 | 药房与样本库连续长程任务，加入任务中断与恢复 | 合格吞吐、自主工时、介入率、质量/安全 |

药房仿真抓取/条码翻转综合成功率 99.8% / 平均 10 秒，与样本库多步骤演示的历史成功，不应直接换算为实机 Worken；需在真实场景取得长期自主运行和人工介入日志。

**实验治理**：Research Agent 不得修改冻结测试集、成功定义或安全阈值。严格分离训练集、验证集、独立 OOD 测试；日志记录 git diff、依赖、训练成本、seed、checkpoint、动作视频和异常回退。优先验证能否用现有本地 Qwen 等模型完成工具编排，不强行等同于云端最强模型能力。
