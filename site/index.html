实体部署与反馈

关键不在“自动生成一个演示”，而在可观察的研发工具链。真实价值需要用固定训练预算、独立测试任务、失败复现和代码版本审计来衡量。

适用于当前项目的结论

  • 先做统一评测接口：优先统一任务、策略、日志、指标，不急于全部重构 RoboLab/RoboDojo。
  • 先做 VLM 纠偏实验：固定 50 步 Chunk 与部分执行重规划、动态窗口、异常检测、恢复策略做消融。
  • 失败驱动数据：对贴边、遮挡、条码方向等典型异常生成受控样本，再在未见场景验收。
  • 谨慎迁移 3.0：四元数顺序和数据 API 有破坏性变化，单独测试，不污染现有基线。
  • Isaac OS 暂缓：仿真研发阶段优先级低于 Agent 工作流和独立评测。
